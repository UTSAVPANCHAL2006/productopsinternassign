01 · Patterns (read this first)

What the 100 apps say

Assignment ask: don’t dump rows — cluster and say where easy wins are vs outreach.

  1. Auth: OAuth2 (56), API key (53), Bearer token (27). Ship OAuth2 + API-key adapters as the default toolkit stack.
  2. Access: 74/100 self-serve · 23/100 paid/admin/partner-gated. Ops capacity should sit on the gated tail, not re-scraping docs.
  3. Buildability: 92/100 are toolkit-ready now (ready / caveats). 7 need outreach before eng starts.
  4. MCP: pass1 over-counted marketplaces as MCP (44) → after cleanup 23 credible MCP signals.
  5. Categories: Dev/Infra + Productivity are the densest self-serve REST wins; niche fintech + thin AI-native apps burn ops time.
  6. Common blocker: OAuth Connected App + sandbox setup friction; many customers require admin install approval.
If I joined ops tomorrow Spend eng time on the self-serve REST majority. Put a human on partner/sales gates and thin-doc apps. Automate the research loop we built here so the next 100 apps don’t start from a blank sheet.

04 · The agent (not by hand)

Pipeline that researched the 100

Python agent: fetch public docs → structure with OpenAI → optional Composio toolkit catalog check → verify → correct.

1 SeedLoad 100 apps from data/apps.json
2 FetchHTTP pull developer docs into evidence packs
3 StructureLLM fills auth / access / API / MCP / verdict JSON
4 VerifySample re-fetch + human/browser handcheck
5 CorrectMCP sanitizer + curated fixes for 403/JS docs
Where a human was needed: 403 / JS-walled docs, missing public API pages, “contact sales” gates, and MCP false positives (marketplace ≠ Model Context Protocol). 20 rows still flagged human in the matrix.
Composio: Composio Platform SDK connected (toolkits list OK). Catalog used as a cross-check only.
